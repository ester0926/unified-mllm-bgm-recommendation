# 輔助實驗說明文件

本文件整理 `user_profiling` 專案中目前已實作的輔助實驗、品質驗證與可視化分析，並說明各實驗可支撐的論文論點。整理重點包含 Stage 3 對話品質、Stage 4 使用者畫像忠實性、Stage 5 偏好向量合理性，以及新增的合成長期偏好可信度驗證。

## 一、整體目的

本研究的主要風險在於：長期偏好向量並非直接來自真實使用者長期互動歷史，而是由合成對話與 LLM 生成之使用者畫像建構。因此，輔助實驗的目的不是宣稱合成偏好等同真實使用者長期偏好，而是補強以下論點：

1. 合成對話本身具有合理品質與 persona 一致性。
2. Stage 4 使用者畫像能忠實反映 Stage 3 source dialogues。
3. 合成使用者畫像與原始音樂 metadata / 正負樣本結構具有可量化對應。
4. 長期偏好表示在音訊、語意與跨模態空間中具有合理性。
5. 不同 LLM 生成器下，合成偏好結構具有一定穩定性。

建議在論文中將這些實驗定位為 synthetic preference validity checks，而非 real-user validation。

## 三、Stage 3 對話品質相關實驗

### 3.1 `quality_evaluator.py`

用途：使用 LLM-as-a-Judge 評估 Stage 3 對話品質，包含：

- Coherence：對話邏輯是否連貫。
- Consistency：使用者是否符合 persona 設定。
- Naturalness：對話是否自然。
- Instruction following：是否遵守生成規則。

可支撐論文論點：

> Stage 3 合成對話並非任意文本，而是經過品質控制與 LLM judge 評估，具有合理對話流、persona 一致性與自然性。

### 3.2 Stage 3 模型選擇、消融與修復實驗

相關檔案：

- `stage3/stage3.1_experiment_model_selection.py`
- `stage3/stage3.2_experiment_ablation.py`
- `stage3/stage3.3_periodic_sampling_eval.py`
- `stage3/stage3.4_diagnose_failures.py`
- `stage3/stage3.5_repair_missing.py`
- `stage3/stage3.6_improved_post_evaluation.py`

用途：

- 比較不同模型或設定的對話生成品質。
- 診斷大規模生成過程中的缺失與失敗案例。
- 補齊缺失資料並進行後驗品質檢查。

可支撐論文論點：

> Stage 3 的合成對話生成並非一次性產出，而是包含模型選擇、消融、抽樣評估、失敗診斷與修復流程，因此具備資料生成品質控管。

## 四、Stage 4 使用者畫像忠實性驗證

### 4.1 `stage4.1_pilot_experiment.py`

用途：測試 profile extraction prompt 與模型設定，作為正式 Stage 4 profile generation 的前置實驗。

可支撐論文論點：

> Stage 4 profile extraction prompt 經 pilot 實驗調整，並非任意設定。

### 4.2 `stage4.2_consistency_eval.py`

用途：使用 LLM-as-a-Judge 比對 Stage 3 source dialogues 與 Stage 4 generated profiles，檢查：

- Accuracy score：profile 是否準確反映 source dialogues。
- Hallucination：profile 是否加入 source dialogues 未提及或無法推論的偏好。
- Omission：profile 是否遺漏重要偏好資訊。

此實驗的定位：

> Stage 4.2 是 profile faithfulness evaluation，而不是 repeated-generation consistency evaluation。

它有做的是：

- 抽樣既有 Stage 4 profiles。
- 使用 LLM judge 評估 profile 與 source dialogues 的一致性。
- 計算 hallucination rate 與 omission rate。

它沒有做的是：

- 隨機抽樣 200 筆後重複生成 5 次。
- 計算 PCS（Preference Consistency Score）。
- 計算 ECS（Explanation Consistency Score）。
- 計算 repeat-based HR。

因此若老師要求「隨機抽樣 200 筆、重複生成 5 次、計算 PCS/ECS/HR」，仍需新增獨立實驗。

論文建議寫法：

> Stage 4.2 evaluates whether generated user profiles are faithful to their source dialogues through LLM-as-a-Judge, focusing on accuracy, hallucination, and omission. This complements, but does not replace, repeated-generation consistency evaluation.

## 五、Stage 5 偏好向量合理性與可視化實驗

### 5.1 `Exp1_audio_gradient.py`

用途：檢查 Stage 2 中 core / exploratory / negative samples 與 target music 的音訊相似度是否符合預期梯度：

```text
Core > Exploratory > Negative
```

主要輸出：

- `experiments/visualization_outputs/exp1_audio_gradient.png`

可支撐論文論點：

> Stage 2 history 的 core、exploratory、negative samples 在音訊空間中呈現合理梯度，支持合成長期偏好歷史具有結構性。

### 5.2 `Exp2_consistency_table.py`

用途：將 Stage 3 dialogues 與 Stage 4 profile 中的 salient facts / conflict tags 視覺化，提供個案層級的一致性展示。

主要輸出：

- `experiments/visualization_outputs/exp2_consistency_table.png`

可支撐論文論點：

> Stage 4 profile 能從 positive / exploratory / negative dialogues 中萃取主要偏好與衝突標籤，並形成可解釋的長期偏好摘要。

### 5.3 `Exp3_semantic_weights.py`

用途：檢查 Stage 5 semantic grounding weights 是否將較高權重分配給與 profile explicit preference 較相符的 core samples。

主要輸出：

- `experiments/visualization_outputs/exp3_semantic_grounding_weights.png`

可支撐論文論點：

> Stage 5 中 explicit preference 的語意加權並非隨機，而是會提高語意相符音樂樣本的權重。

### 5.4 `Exp4_dual_tsne.py`

用途：從文字空間、音訊空間與跨模態投影空間檢查偏好向量合理性，包含：

- Text space t-SNE。
- Cross-modal alignment。
- Cross-modal Hit@K。
- Audio space t-SNE 與 convex hull。

主要輸出：

- `experiments/visualization_outputs/exp4_dual_tsne.png`

可支撐論文論點：

> Stage 5 的偏好表示在跨模態空間中具備可觀察的語意與音訊對齊效果。

## 六、Synthetic-to-real Validity Analysis

### 6.1 `synthetic_to_real_validity_analysis.py`

用途：回應審稿人可能質疑：

> 你說長期偏好有效，但這些偏好是合成的，是否只是 LLM 生成資料帶來的人工規律？

此實驗檢查以下面向：

1. 用戶畫像與原始音樂 metadata 的一致性。
2. 偏好描述與正樣本音樂特徵的對齊程度。
3. 偏好描述與負樣本音樂特徵的區辨能力。
4. 不同 LLM 生成器下的穩定性。

主要輸出：

- `experiments/synthetic_validity_outputs/synthetic_validity_case_metrics.csv`
- `experiments/synthetic_validity_outputs/synthetic_validity_summary.json`
- `experiments/synthetic_validity_outputs/synthetic_validity_report.md`
- `experiments/synthetic_validity_outputs/stage4_profiles_gemma3_12b.jsonl`
- `experiments/synthetic_validity_outputs/stage4_profiles_llama3_8b.jsonl`

### 6.2 已完成的主要結果

目前 1,000 筆 synthetic-to-real validity analysis 結果：

| 指標 | 數值 | 解讀 |
|---|---:|---|
| Grounding ratio mean | 0.6365 | profile 屬性約 63.65% 可由 metadata/history 支持 |
| Grounding ratio median | 0.6667 | 典型 case 約三分之二屬性具資料支持 |
| Positive alignment mean | 0.5859 | profile 正向偏好與正樣本有中等程度對齊 |
| Negative preference overlap mean | 0.2605 | 正向偏好與負樣本重疊偏低 |
| Discrimination margin mean | 0.3253 | 正樣本對齊高於負樣本重疊 |
| Positive-vs-negative win rate mean | 0.6359 | profile 對正樣本匹配通常高於負樣本 |
| Coherence lift mean | 0.1478 | 同一使用者正樣本比隨機音樂更一致 |
| Synthetic-to-metadata JSD | 0.0459 | 合成屬性分布與 metadata 分布差距小 |

跨 LLM 穩定性結果：

| 指標 | 數值 |
|---|---:|
| Models | Gemma 3 12B vs LLaMA 3 8B |
| Common cases | 300 |
| Mean attribute Jaccard | 0.6948 |
| Median attribute Jaccard | 0.7000 |
| Jaccard >= 0.5 | 90.3% |
| Jaccard >= 0.7 | 53.0% |

論文建議結論：

> 合成長期偏好不是完全任意的 LLM 生成文字，而是具有 metadata grounding、正負樣本區辨能力，以及跨 LLM 生成器下的中高程度穩定性。然而，本研究仍不主張其等同於真實使用者長期歷史，而是將其定位為 synthetic preference proxy。

## 七、尚未實作但可作為後續補強的實驗

### 7.1 Repeat-generation Consistency Evaluation

老師提到的：

> 隨機抽樣 200 筆合成資料，重複生成 5 次，計算偏好 PCS 與解釋 ECS 一致性分數及幻覺率 HR。

目前尚未實作。建議新增獨立程式：

```text
experiments/repeated_generation_consistency_eval.py
```

建議設計：

1. 隨機抽樣 200 個 music_id。
2. 對每個 music_id 使用同一個 LLM 重複生成 5 次 profile / explanation。
3. 抽取每次生成的 preference attributes 與 explanation attributes。
4. 計算：
   - PCS：Preference Consistency Score。
   - ECS：Explanation Consistency Score。
   - HR：Hallucination Rate。

建議定義：

```text
PCS = 同一 case 5 次生成 profile preference attributes 的兩兩 Jaccard 平均
ECS = 同一 case 5 次生成 explanation attributes 的兩兩 Jaccard 平均
HR  = unsupported generated attributes / total generated attributes
```

與現有實驗的差異：

| 實驗 | 驗證問題 |
|---|---|
| Stage 4.2 consistency eval | profile 是否忠實於 source dialogues |
| Synthetic-to-real validity | profile 是否 grounded in metadata/history |
| Multi-generator stability | 不同 LLM 是否生成相似偏好結構 |
| Repeat-generation PCS/ECS/HR | 同一 LLM 重複生成是否穩定 |

因此 PCS/ECS/HR 是尚未完成但可補強的自動一致性驗證。
